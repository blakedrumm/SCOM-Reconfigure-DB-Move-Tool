## Bug Fixes

- Preserve long SQL instance names, including DNS aliases with named instances, in OperationsManager and Data Warehouse updates, audit output, and database previews.
- Use Unicode SQL parameters and safely quoted identifiers and connection strings.
- Capture before/after audit values from the row actually updated, including multi-row log tables.
- Roll back the affected database's table updates when a value exceeds a destination column's capacity or a required column is missing.
- Stop subsequent database and cache steps when a database job fails, and preserve SQL errors and caller-owned connections.
- Ensure Windows PowerShell 5.1 reads the multilingual script as UTF-8.

## Downloads

The distribution layout is unchanged: an x64 EXE ZIP, a combined x86/x64 EXE ZIP, an x64 MSI ZIP, and the standalone PowerShell script. The executables use the native SAPIEN PowerShell V5 Windows Forms hosts. Runtime configuration, icons, installer paths, and the Start Menu shortcut are retained. The MSI remains in the existing upgrade family and uses new product and package identities.

## Validation

Automated database-query, background-job, and disposable LocalDB tests pass under Windows PowerShell 5.1 and PowerShell 7. Package checks compare the assets with v2.5.0.0 and verify checksums, architectures, versions, native resources, MSI metadata, and the embedded x64 payload.

The packages are unsigned, as in the previous release. No production SCOM databases were used, and an elevated fresh-install/upgrade/uninstall test was not performed. Validate installation and the complete migration workflow in your test environment before production use. Transactions apply within each database, not across the complete migration.
